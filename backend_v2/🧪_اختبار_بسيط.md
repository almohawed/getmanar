# 🧪 اختبار Container البسيط

## الخطوة 1: اختبار النسخة المبسطة أولاً

لنتأكد أن المشكلة ليست في Docker نفسه، سنختبر نسخة بسيطة جداً:

```powershell
cd C:\Users\asus\my\almadrasah\backend_v2

gcloud run deploy schedule-solver-test --source . --dockerfile Dockerfile.test --region us-central1 --allow-unauthenticated --project etisak-784d6
```

إذا نجح هذا، المشكلة في الكود الأساسي.
إذا فشل، المشكلة في إعدادات Cloud Run.

---

## الخطوة 2: نشر النسخة الكاملة

بعد التأكد من نجاح الاختبار، نشر النسخة الكاملة:

```powershell
gcloud run deploy schedule-solver --source . --region us-central1 --allow-unauthenticated --timeout 300 --memory 2Gi --cpu 2 --project etisak-784d6
```

لاحظ التغييرات:
- زيادة الذاكرة إلى 2Gi (بدلاً من 1Gi)
- زيادة CPU إلى 2 (بدلاً من 1)
- هذا لأن OR-Tools يحتاج موارد أكثر

---

## الخطوة 3: فحص Logs

إذا فشل، افتح الرابط الذي يظهر في الخطأ:
```
https://console.cloud.google.com/cloud-build/builds;region=us-central1/...
```

ابحث عن:
- `ERROR` في الـ logs
- `ModuleNotFoundError`
- `ImportError`
- أي رسالة خطأ حمراء

---

## 💡 الحلول المحتملة

### إذا كانت المشكلة في OR-Tools:
```
ERROR: Could not find a version that satisfies the requirement ortools
```

الحل: استخدام Python 3.10 بدلاً من 3.11:
```dockerfile
FROM python:3.10-slim
```

### إذا كانت المشكلة في الذاكرة:
```
Container killed due to memory limit
```

الحل: زيادة الذاكرة:
```
--memory 2Gi
```

### إذا كانت المشكلة في Timeout:
```
Container failed to start within allocated time
```

الحل: زيادة timeout:
```
--timeout 600
```
